## 1. 背景与问题

本 PRD 是 Bid Master Web 总产品需求文档 `specs/pm/pr.spec.md` 的功能级补充，承接其中新增的 `AFF-09: 项目查询`。项目查询不是替换现有要素提取、模拟编制、开标分析、文件管理和报告导出能力，而是在保持当前功能体系不变的基础上，补齐招投标全流程中“查找项目信息”这一前置环节。

Bid Master Web 当前核心能力集中在“拿到招标文件之后”的分析工作，包括要素提取、模拟编制、开标分析和报告导出。用户提出希望平台真正覆盖招投标全部工作，其中第一步是“查找项目信息”。

用户初始想法是在功能区增加一个“项目查询”页面，让用户添加自己关注的网页链接，并在页面中点击链接按钮直达目标网站。这个想法本质上不是搜索引擎，而是“招投标信息源管理 + 项目线索入口”。

因此，本 PRD 将需求收敛为一个可落地的 MVP：先帮助用户统一管理常用招投标信息网站、地区公共资源交易平台、企业采购平台和项目线索链接，再逐步扩展为项目订阅、更新提醒和 AI 辅助筛选。

## 2. 产品目标

### 2.1 总目标

让用户在 Bid Master Web 中完成招投标工作流的第一步：集中管理和访问项目信息来源，减少在浏览器收藏夹、聊天记录、Excel 表格之间反复查找链接的成本。

### 2.2 阶段目标

| 阶段 | 目标 | 说明 |
|------|------|------|
| MVP | 用户可保存、分类、搜索、打开常用项目查询链接 | 先做稳定可靠的人工维护型信息源入口 |
| v1 | 用户可记录具体项目线索，并关联文件与分析结果 | 把“看到项目”连接到“分析项目” |
| v2 | 支持信息源状态检查、更新提醒、关键词订阅 | 逐步从静态链接管理走向项目机会追踪 |
| v3 | AI 辅助解析网页或公告内容 | 在合规前提下辅助摘要、筛选、归档 |

## 3. 目标用户

| 用户类型 | 使用动机 | 典型场景 |
|----------|----------|----------|
| 投标方 | 快速找到潜在投标项目 | 每天查看各地区公共资源交易平台、企业采购平台 |
| 招标方/代理机构 | 跟踪类似项目公告和市场信息 | 参考历史公告、竞品项目、采购趋势 |
| 评标/咨询人员 | 查询公告、澄清、开标信息 | 在评审前后核验项目信息来源 |

## 4. 用户故事

### US-01：添加常用查询网站

作为投标方用户，我希望把常用公共资源交易平台和企业采购平台链接保存到系统里，这样每天打开 Bid Master Web 后就能直接进入对应网站查项目。

**验收标准：**

- 用户可以新增链接名称、URL、分类、地区、备注。
- URL 必须是合法的 `http` 或 `https` 地址。
- 保存后链接出现在“项目查询”页面。
- 点击链接时在新标签页打开目标网站。

### US-02：按分类和地区查找链接

作为经常查询多个地区项目的用户，我希望按地区、平台类型或关键词筛选链接，避免链接数量增加后难以查找。

**验收标准：**

- 用户可以按分类筛选：公共资源交易平台、政府采购、企业采购、行业平台、其他。
- 用户可以按地区筛选：全国、省、市或自定义地区。
- 用户可以按名称、备注、URL 关键词搜索。

### US-03：管理链接有效性

作为长期使用平台的用户，我希望能看到哪些链接可能失效，避免点击后才发现网站打不开。

**验收标准：**

- MVP 先提供“最后访问时间”和“手动标记失效”。
- v1 可增加“检查链接状态”按钮，由后端请求目标 URL 并返回可访问状态。
- 链接失效不自动删除，只提示用户处理。

### US-04：记录项目线索

作为投标方用户，我希望不仅保存网站入口，还能把某个具体项目链接保存为项目线索，后续上传招标文件后能关联到这个线索。

**验收标准：**

- 用户可以从项目查询页新增“项目线索”。
- 项目线索至少包含：项目名称、公告链接、地区、项目阶段、备注。
- 项目阶段支持：招标公告、预公示、澄清答疑、开标结果、中标候选人、中标结果、其他。
- 项目线索可关联已上传文件或分析结果。

## 5. 功能范围

### 5.1 MVP 必做功能

#### AFF-09：项目查询入口

**层级：** 初级  
**启用动作：** 用户进入独立页面，查看并打开常用项目查询网站。

| 功能点 | 描述 |
|--------|------|
| 新增链接 | 添加网站名称、URL、分类、地区、备注 |
| 链接列表 | 以卡片或表格展示已保存链接 |
| 快捷打开 | 点击“打开网站”在新标签页打开 URL |
| 搜索筛选 | 按关键词、分类、地区筛选 |
| 编辑删除 | 修改链接信息或删除不再使用的链接 |
| 默认示例 | 可提供少量系统内置示例，但用户可隐藏或删除自己的收藏 |

#### AFF-10：链接分类管理

**层级：** 初级  
**启用动作：** 用户把信息源整理为可浏览结构。

| 分类 | 说明 |
|------|------|
| 公共资源交易平台 | 全国、省、市公共资源交易中心 |
| 政府采购 | 政府采购网、财政采购平台 |
| 企业采购 | 国企、央企、集团采购平台 |
| 行业平台 | 建设工程、交通、水利、能源等行业平台 |
| 第三方聚合 | 招标信息聚合网站 |
| 其他 | 用户自定义来源 |

### 5.2 v1 建议功能

#### AFF-11：项目线索管理

**层级：** 次级  
**启用动作：** 用户把某个具体公告或项目保存为待跟进线索。

| 功能点 | 描述 |
|--------|------|
| 新增线索 | 保存具体项目名称、公告 URL、阶段、地区、备注 |
| 线索状态 | 待关注、已下载文件、已分析、已投标、已归档 |
| 关联文件 | 与上传的 tender_doc 建立关联 |
| 关联分析 | 与 element_extract、simulated_doc、opening_analysis 建立关联 |
| 时间记录 | 创建时间、最后更新时间、截止时间 |

### 5.3 v2 可选功能

| 功能 | 说明 | 风险 |
|------|------|------|
| 链接可用性检查 | 后端检查 HTTP 状态码 | 部分网站反爬或限制访问，不能保证准确 |
| 关键词订阅 | 用户保存关键词，如“装修”“监理”“智能化” | 需要明确数据来源和抓取边界 |
| 更新提醒 | 对已保存线索提醒用户复查 | MVP 可先用人工提醒，不做自动爬取 |
| 批量导入链接 | 支持 CSV/Excel 导入信息源 | 需要格式模板和错误提示 |

### 5.4 明确不做范围

| 不做内容 | 原因 |
|----------|------|
| MVP 不做全网招标搜索引擎 | 数据源复杂、合规风险高、成本高 |
| MVP 不自动爬取第三方网页内容 | 需遵守网站 robots、版权、访问限制和反爬策略 |
| MVP 不承诺网站内容实时更新 | 第一版定位是用户自定义信息源管理 |
| MVP 不自动代替用户报名或投标 | 涉及法律责任和账号权限风险 |

## 6. 交互设计需求

### 6.1 页面入口

在功能区工作台侧边栏新增入口：`项目查询`。顶部全局导航不单独增加“项目查询”按钮，用户先进入“功能”页面，再从功能区侧边栏进入项目查询。

建议导航位置：

```text
功能 / 项目查询
```

入口规则：

- 顶部全局导航只保留“功能”入口。
- 项目查询仅出现在功能区工作台侧边栏。
- 项目查询页面本身仍使用工作台布局，和要素提取、模拟编制、开标分析保持一致。

### 6.2 页面结构

```text
项目查询
├── 顶部操作区
│   ├── 搜索框：搜索网站名称、地区、备注
│   ├── 分类筛选
│   ├── 地区筛选
│   └── 新增链接按钮
├── 推荐/常用区
│   ├── 最近访问
│   └── 我的常用
├── 链接列表区
│   ├── 卡片视图
│   └── 表格视图（可后置）
└── 项目线索区（v1）
    ├── 待关注项目
    ├── 已关联文件项目
    └── 已完成分析项目
```

### 6.3 链接卡片字段

| 字段 | 是否必填 | 示例 |
|------|----------|------|
| 名称 | 是 | 浙江省公共资源交易服务平台 |
| URL | 是 | https://example.com |
| 分类 | 是 | 公共资源交易平台 |
| 地区 | 否 | 浙江省 |
| 标签 | 否 | 建设工程、政府采购 |
| 备注 | 否 | 每天上午查看公告和澄清 |
| 是否常用 | 否 | 是/否 |
| 最后访问时间 | 系统生成 | 2026-07-09 10:00 |

### 6.4 关键交互

| 动作 | 反馈 |
|------|------|
| 新增链接成功 | Toast 提示“链接已保存” |
| URL 不合法 | 表单内提示“请输入有效的 http/https 链接” |
| 点击打开 | 新标签页打开，同时更新最后访问时间 |
| 删除链接 | 二次确认，防止误删 |
| 搜索无结果 | 显示空状态和“新增链接”引导 |

## 9. 权限与安全约束

引用 `.42cog/real/real.md` 的安全原则：用户上传和业务数据可能包含敏感商业信息，必须按用户隔离。

| 约束 | 要求 |
|------|------|
| 用户隔离 | 用户只能查看、编辑、删除自己的链接和项目线索 |
| URL 校验 | 仅允许 `http://` 和 `https://`，禁止 `javascript:`、`file:` 等危险协议 |
| 外链打开 | 使用新标签页打开外部链接，并加 `noopener noreferrer` |
| 自动抓取限制 | MVP 不抓取第三方网页内容，避免合规和反爬风险 |
| 敏感信息 | 不在链接备注中要求用户填写账号密码、CA 证书、投标密钥等敏感信息 |

## 13. 产品决策记录

| 决策 | 说明 |
|------|------|
| 第一版做链接与线索管理，不做全网搜索 | 降低合规风险和实现复杂度，先解决用户每日入口分散的问题 |
| 项目查询作为独立一级页面 | 符合“招投标全流程第一步”的定位，用户可直接感知 |
| 信息源和项目线索分阶段实现 | 信息源是高频刚需，项目线索是下一层工作流连接点 |
| 保留后续 AI 扩展空间 | 后续可把公告内容接入要素提取、文件管理和报告导出 |
